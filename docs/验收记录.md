浏览器测试六项分别验证：

1. 客服创建工单，生成退款提案，查看证据和五个执行节点；独立 reviewer 审批后账本与审计更新，重新登录仍保留记录。
2. 拒绝另一退款方案，工单进入拒绝终态，账本金额不变。
3. 证据不足及提示注入案例转人工，不产生审批或退款。
4. 切换租户后工单、知识库与审计界面不显示原租户内容。
5. 失败 run 的结构化错误可读，页面不崩溃且可继续导航。**仅此异常 UI 测试使用响应 mock**；模型协议异常由后端测试覆盖。
6. 390px 宽度下登录、工作台、新建弹窗、审批、知识库与审计页面无文档级横向溢出。

独立审查额外发现并修复“回答中追加伪造引用”的校验缺口。临时数据库探针确认：在退款写入后人为令审计失败，订单余额、账本、审批状态与幂等响应全部回滚；供应商非法 JSON、未知动作、HTTP 429 不创建审批或退款，且不回显供应商错误正文。这些探针不额外计入 30 项 pytest。

## 结果解释

**30 项后端测试、12 条合成场景与 6 项浏览器测试分开计数，不能加总为模型准确率。** 12 条场景采用规则演示 provider；真实模型适配使用 MockTransport 验证协议。尚未使用真实供应商 API Key 测量回答质量、检索召回率、费用或延迟分布。

未验证生产吞吐、高可用、真实支付、外部不可篡改审计。机器没有 Docker，因此本地未执行镜像构建；2026-10-26 的 GitHub CI 已确认两个镜像构建成功，未验证实际云端部署、持久卷备份或生产流量。没有声称已运行上游开源项目的完整测试。

## 复现入口

具体命令见根 README。后端测试及评估使用临时数据库；E2E 使用 `8001` + `5174` 测试服务，与 `8000` + `5173` 交互演示隔离。重跑不应清除用户演示数据。

场景评估原始输入：[`backend/evals/cases.json`](../backend/evals/cases.json)。输出：[`backend/evidence/eval-demo.json`](../backend/evidence/eval-demo.json)。真实模型评估需要显式设置模型环境并执行 `--provider configured --allow-model-network`，该操作可能产生供应商费用。
